## 1. Введение

Работа с большими наборами точек часто требует много времени. Последовательные алгоритмы испытывают проблемы с производительностью и не превосходят ожидания пользователя. Это происходит из-за того, что программа использует не всю доступную ей вычислительную мощность. Параллельные версии должны ускорить работу программы, задействовав все доступные ресурсы аппаратного обеспечения.



## 2. Постановка задачи

Требуется разработать программу, которая строит выпуклую оболочку проходом Джарвиса. Необходимо реализовать последовательную и параллельную версию с помощью технологии MPI.
Вход: std::vector<std::pair<double,double>> - набор точек.

Выход: std::vector<std::pair<double,double>> - вектор с точками выпуклой оболочки.



## 3. Базовый Алгоритм (Последовательный)

При решении задачи используется алгоритм Джарвиса:

1. Из набора точек удаляются повторяющиеся точки.
2. Находится левая нижняя точка.
3. Текущая точка - левая нижняя.
4. Делай,
    4.1. Добавить в вектор оболочки текущую точку.
    4.2. Цикл до размера набора точек:
        4.2.1. Если индекс цикла совпадает с текущей точкой, то продолжить.
        4.2.2. Если следующая точка не выбрана, то выбираем первую точку.
        4.2.3. Вычисляем ориентацию текущей, следующей точек и точки под индексом цикла.
        4.2.4. Если ориентация больше нуля - следующая точка - точка под интексом цикла.
        4.2.5. Иначе если ориентация равна нулю - вычисляем расстояние между точками и берем самую дальнюю.
    4.3. Присваиваем текущей точке значение следующей.
    Пока (Текущая точка не равна левой нижней точке).



## 4. Схема распараллеливания

На корневом процессе вычисляются индексы частей набора точек обработки для каждого процесса, также на нем вычисляется левая нижняя точка. После идет перессылка индексов с помощью MPI_Scatter, левой нижней точки - с помощью MPI_Bcast. В главном цикле на корневом процессе происходит добавление в точки в вектор выпуклой оболочки, затем рассылка всем процессам новой текущей точки. Каждый процесс, при условии наличия у него точек для обработки, находит своего локального кандидата на добавление. После, с помощью MPI_Gather, все локальные кандидаты передаются корневому процессу, который выбирает истинного кандидата. После главного цикла идет рассылка результата всем процессам.


## 5. Детали реализации

В параллельной реализации происходит подсчет индексов частей набора точек обработки для каждого процесса, а не отправка кусков набора, что ускоряет работу программы и уменьшает работу с памятью.
